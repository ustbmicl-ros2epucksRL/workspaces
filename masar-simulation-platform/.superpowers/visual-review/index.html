MASAR 仿真验证平台

架构与工作台评审 · 方案 A

运行架构

单一控制入口管理一个活动运行；ROS 数据、仿真画面和桌面画面走独立通道，任何一个可视化组件失效都不应终止仿真。

浏览器 · 单端口
任务控制台场景选择、预检、启动、停止、START / STOP / HOME
ROS 可视化地图、TF、轨迹、LaserScan、图像与指标
仿真视图Webots W3D；Gazebo / RViz noVNC
⇄
新平台 · 独立部署
Reverse Proxy + Platform APIREST / WebSocket、单运行锁、状态机、命令审计、运行归档
场景目录与编排器合法组合、参数 Schema、预检、就绪条件、退出策略
ROS1 / ROS2 Web Gatewayrosbridge、TF republisher、web_video_server、话题白名单
Visual Desktop SidecarTurboVNC / noVNC；隔离 Gazebo、RViz 和可选 Qt 桌面
⇄
现有容器 · 保持原逻辑
masar_ros1_srv-gROS1 Noetic、Gazebo、RoboSAR、Qt；平台代理按进程组管理
masar_ros2_bridge-wROS2 Humble、Webots R2025a、群行为、ROS1 bridge
现有启动脚本默认行为不变；平台功能仅由显式可选参数启用
隔离原则：平台停止只终止当前 run_id 创建的进程组；不得使用模糊的 pkill，不得清理不属于本次运行的 ROS 图或容器进程。

统一工作台

操作区保持固定，仿真、地图、任务与日志可调整尺寸。搜救场景显示完整业务状态；普通群行为场景自动隐藏无关面板。

职责边界

平台管理运行，ROS 网关只传数据，现有容器继续承载业务和仿真。

主工作流

先配置并预检，再进入运行工作台；停止运行和任务 STOP 是两个不同命令。

信息密度

仿真与地图居中，任务状态常驻右侧，日志和时间线固定在底部。
